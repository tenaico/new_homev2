# 회사 홈페이지(tenai.kr) 운영 매뉴얼

> 기준일 2026-11-13. 기준 코드는 홈페이지 저장소의 원격 main(마지막 반영 PR #34, 11/12).
> 화면의 메뉴·단추·안내 문구는 관리자 화면(`/admin`) 코드에 적힌 글자를 그대로 옮겼다. 따옴표("") 안의 글자가 화면에 보이는 글자다.
> 이 홈페이지가 무엇이고 왜 이렇게 생겼는지는 [프로젝트 이해 문서](프로젝트이해.md)에 있다. 이 매뉴얼은 "따라 하는 순서"만 다룬다.

**누가 어느 부를 읽나**
- 운영 담당자(글·배너·상담을 다루는 사람): 1부, 2부, 자주 막히는 곳, 자주 묻는 질문.
- 코드를 고쳐 배포하는 담당자(개발자): 전부. 특히 3부, 4부.
- 교육 콘텐츠를 만드는 대표: 각 장 첫 줄의 "결론"과 표. 각 장이 강의 슬라이드 한 장 단위다.

**한 장으로 보는 구조**: 글은 "관리자 화면 → 데이터베이스 → 사이트"로 저장 즉시 바뀌고, 디자인은 "코드 → 저장소 → 자동 배포"로 몇 분 뒤 바뀐다. 비유하면 관리자 화면은 매장 앞 칠판(분필로 바로 고침)이고, 코드는 간판(공사가 필요함)이다. 자세한 그림은 [프로젝트 이해 6장](프로젝트이해.md#6-어떻게-돌아가나)에 있다.

## 1부. 관리자 페이지로 운영하기

### 1-1. 로그인과 잠금(M1)

결론: 관리자 아이디와 비밀번호로 들어가고, 일이 끝나면 반드시 "잠금"을 누른다. 비밀번호는 메일로 찾을 수 없다.

**어디서**: 브라우저 주소창에 `tenai.kr/admin`을 넣는다. 모든 쪽 바닥글의 관리자 콘솔 링크로도 온다.

**따라 하기: 로그인**
1. `tenai.kr/admin`을 연다.
2. 화면 가운데 "TEN AI 관리자 콘솔"과 "관리자 계정으로 로그인하세요"가 보이는지 확인한다.
3. 첫 칸 "관리자 아이디"에 아이디를 넣는다. 이메일 형식 아이디도 그대로 넣어도 된다.
4. 둘째 칸 "비밀번호"에 비밀번호를 넣는다.
5. "접속하기"를 누른다(엔터 키도 된다).
6. 아래쪽에 "관리자로 로그인되었습니다."가 잠깐 뜨고, 왼쪽에 메뉴 10개가 나오면 성공이다.
7. 오른쪽 위 작은 표시가 "Supabase 연결됨"인지 본다. 이것이 실제 데이터베이스(Supabase, 글·문의를 저장하는 클라우드 창고)에 연결되었다는 뜻이다.

**따라 하기: 잠금(로그아웃)**
1. 오른쪽 위 "잠금"을 누른다.
2. 화면이 다시 로그인 상자로 바뀌는지 확인한다.

**화면 위쪽 단추**: "사이트 보기 ↗"는 첫 화면(현관)을 연다. 저장한 내용을 확인할 때 쓴다.

**주의할 점**
- 로그인 상태는 브라우저에 남는다. 잠금을 누르지 않고 창만 닫으면, 다음에 `/admin`을 열 때 비밀번호 없이 바로 열린다. 공용 PC에서는 반드시 "잠금"을 누른다.
- "로그인 실패: 아이디 또는 비밀번호를 확인하세요."가 뜨면 오타를 확인한다. 비밀번호를 잊었으면 개발자에게 다시 정해 달라고 요청한다(4부 4-4).
- "관리자 계정이 아닙니다. 일반 회원은 사이트의 멤버십을 이용해 주세요."는 관리자 권한이 없는 계정으로 들어온 경우다. 권한은 데이터베이스가 계정마다 따로 표시해 두며([프로젝트 이해 2-7절](프로젝트이해.md#2-7-회원-기능이-붙으면-무엇이-달라지나)의 RLS), 화면을 조작해도 바뀌지 않는다.
- 아이디·비밀번호는 이 문서, 메신저, PR 본문에 적지 않는다. 담당자끼리 직접 전달한다.

### 1-2. ⚙️ 사이트 설정(M2)

결론: 여기서 바꾼 연락처·주소·슬로건은 모든 쪽에 바로 걸린다. 다만 "메인 타이틀 1·2행"은 첫 화면(`/`)과 회사 홈(`/biz`)에는 반영되지 않는다.

**어디서**: 왼쪽 메뉴 "⚙️ 사이트 설정". 로그인하면 처음 열리는 화면이다.

**무엇을 넣으면 → 어디에 보이나**

| 칸(화면 글자) | 넣는 것(예) | 사이트에서 보이는 곳 |
|---|---|---|
| 상단 배지 문구 | 짧은 영문 표어 한 줄 | 학습 홈(`/learn`) 맨 위 "학습 홈 · " 뒤의 작은 글자 |
| 메인 타이틀 1행 | "AI를 배우는 시대에서," | 학습 홈 큰 제목 첫 줄만. **첫 화면·회사 홈에는 반영 안 됨** |
| 메인 타이틀 2행 (강조색) | "AI로 배우는 시대로" | 학습 홈 큰 제목 둘째 줄만. **첫 화면·회사 홈에는 반영 안 됨** |
| 서브 타이틀 (줄바꿈 반영) | 소개 문장 2~3줄 | 학습 홈 큰 제목 아래 소개 글. 엔터 친 곳이 그대로 줄바꿈 |
| 문의 이메일 | 회사 공용 문의 주소 | 모든 쪽의 메일 문의 링크, 메일 주소 복사 단추 |
| 유튜브 채널 URL | `https://`로 시작하는 채널 주소 | 유튜브 채널 링크 |
| 주소 | 회사 주소 | 모든 쪽 바닥글 주소 |
| 푸터 슬로건 | 한 줄 슬로건 | 모든 쪽 바닥글 슬로건 |

**따라 하기**
1. "⚙️ 사이트 설정"을 누른다.
2. "메인 화면 문구" 상자에서 바꿀 칸만 고친다.
3. "연락처 & 링크" 상자에서 바꿀 칸만 고친다.
4. 맨 아래 "💾 설정 저장"을 누른다.
5. "설정이 저장되었습니다. 사이트에 즉시 반영됩니다."가 뜨는지 본다.
6. 새 탭에서 바꾼 자리(위 표의 오른쪽 칸)를 열고 새로고침해 확인한다.

**주의할 점**
- 칸을 비우고 저장하면 사이트는 코드에 적힌 원래 문구를 보여 준다. "지운다"가 아니라 "원래대로"다.
- 유튜브 주소는 `http://`나 `https://`로 시작해야 링크가 바뀐다. 아니면 이전 링크가 남는다.
- 화면을 영어(EN)로 보는 동안에는 이 문구가 걸리지 않는다. 영어 문구는 번역 사전이 맡는다. 링크(메일·유튜브)는 언어와 상관없이 바뀐다.
- 검색엔진이 읽는 사본에는 이 문구가 들어가지 않는다. 검색 결과에 보이는 첫머리 글을 바꾸려면 코드를 고쳐야 한다(3부).
- "관리자 암호" 상자는 데이터베이스에 연결된 정상 상태에서는 보이지 않는다. 보이면 연결이 끊긴 것이다(자주 막히는 곳 1번).

### 1-3. 📊 접속 통계(M4)

결론: 방문을 "개인을 알아볼 수 없는 합계"로만 보여 준다. 누가 왔는지는 볼 수 없고, 어느 쪽이 많이 읽히는지 본다.

**어디서**: 왼쪽 메뉴 "📊 접속 통계".

**따라 하기**
1. "📊 접속 통계"를 누른다.
2. 오른쪽 위 기간 단추 "7일", "30일", "90일" 중 하나를 누른다.
3. 위쪽 숫자 판을 읽는다: "오늘 방문자", "오늘 페이지뷰", "최근 7일 방문자", "누적 방문자", "최근 7일 방문 수", "최근 7일 페이지뷰", "누적 페이지뷰".
4. "날짜별 방문자" 그래프에서 "방문자"와 "페이지뷰"를 눌러 바꿔 본다. 그래프를 누르고 왼쪽·오른쪽 화살표 키로 날짜를 옮길 수 있다.
5. 숫자를 표로 보려면 그래프 아래 "표로 보기"를 누른다.
6. "많이 본 쪽"(페이지뷰 상위 10곳), "어디서 왔나"(네이버 검색, 유튜브, "직접 방문 · 즐겨찾기" 등), 맨 아래 "기기"(모바일·태블릿·데스크톱 비율)를 본다.
7. 숫자가 오래된 것 같으면 "새로고침"을 누른다.

**용어**: 방문자는 그날 들어온 사람 수(같은 사람이 여러 번 와도 하루 1명), 페이지뷰는 열린 쪽 수, 방문 수는 새로 들어온 횟수다.

**주의할 점**
- 기록은 2026년 10월 16일부터 쌓인다. 그 전 기간은 0으로 보인다.
- 날짜는 한국 시간 자정 기준이다.
- 세지 않는 방문: 배포 미리보기 주소, 자동화 브라우저, 브라우저에서 "추적 안 함"을 켠 방문. 그래서 실제 방문보다 조금 적게 나온다.
- "어디서 왔나"에는 검색어와 주소의 나머지 부분을 남기지 않는다. "무슨 검색어로 왔나"는 이 화면으로 알 수 없다.
- 기록은 1년이 지나면 저절로 지워진다.

### 1-4. 📋 게시물 관리(M5)

결론: 소식 한 건은 제목·분류·내용·상단 고정 네 가지로 끝난다. 저장하면 `/news`와 첫 화면·회사 홈의 최근 소식에 바로 나온다. 실제 하루 예시는 [프로젝트 이해 5장](프로젝트이해.md#5-하루-따라가기-운영-담당자가-새-소식을-올리는-날).

**따라 하기: 새 소식 올리기**
1. "📋 게시물 관리"를 누른다.
2. 상자 제목이 "새 게시물 작성"인지 본다. "게시물 수정"이면 "새로 작성"을 먼저 누른다.
3. "제목"에 제목을 넣는다. 예: "12월 생성형 AI 실무 교육 일정 안내".
4. "분류"에서 하나를 고른다. 기본 분류는 공지·뉴스·교육이다.
5. "내용 (줄바꿈 반영)"에 본문을 쓴다. 엔터 친 곳이 사이트에서도 줄바꿈된다.
6. 목록 맨 위에 계속 두려면 "상단 고정"에 체크한다.
7. "💾 게시물 저장"을 누른다.
8. "게시물이 저장되었습니다."를 확인한다.
9. 새 탭에서 `tenai.kr/news`를 열어 글과 분류 배지를 확인한다.

**따라 하기: 고치기와 지우기**
1. 아래 "게시물 목록"에서 해당 글의 "수정"을 누른다.
2. 위 상자가 "게시물 수정"으로 바뀌고 내용이 채워진다.
3. 고친 뒤 "💾 게시물 저장"을 누른다.
4. 지우려면 목록에서 "삭제"를 누른다.
5. "이 게시물을 삭제할까요? 되돌릴 수 없습니다." 창에서 "확인"을 누른다.

**주의할 점**
- 제목이 비면 "제목을 입력하세요."가 뜨고 저장되지 않는다.
- 삭제는 되돌릴 수 없다. 내리기만 하려면 삭제 대신 내용 백업을 먼저 해 둔다(이 메뉴에는 "숨김" 기능이 없다).
- 목록에 "📌 고정"이 붙은 글은 상단 고정 글이다. 11/13 현재 소식 4건이 모두 고정이라, 새 글을 고정하면 고정 글끼리 날짜 순으로 선다.
- 관리자가 쓴 글은 영어로 자동 번역되지 않는다. 해외용 공지는 본문에 영어 문장을 함께 쓴다.

### 1-5. 📚 핸드북 관리(M7)

결론: 핸드북은 "교재 카드"다. 교재 파일 자체를 올리는 곳이 아니라, 교재가 있는 웹 주소를 카드로 걸어 두는 곳이다.

**사이트에서 보이는 곳**: `/education`의 핸드북 탐색기(과정 → 레벨 두 단계), `/news` 세 창구 현황의 핸드북 수.

**따라 하기**
1. "📚 핸드북 관리"를 누른다.
2. 상자 제목이 "새 핸드북 등록"인지 본다.
3. "제목"을 넣는다.
4. "과정 (분류)"를 고른다. 이 값이 탐색기의 과정 탭이 된다.
5. "레벨"에서 "Level 1"~"Level 4" 중 하나를 고른다.
6. "접근 권한"에서 "전체 공개"를 고른다(아래 주의할 점 참고).
7. "소개 문구"에 카드에 나올 한두 문장을 쓴다.
8. "웹 링크 URL"에 교재 주소를 넣는다. 예: `https://`로 시작하는 문서 주소.
9. "링크 열기 방식"에서 "새 창(새 탭)에서 열기"를 고른다.
10. "💾 핸드북 저장"을 누른다.
11. "핸드북이 저장되었습니다. 사이트에 즉시 반영됩니다."를 확인한다.
12. `/education`에서 해당 과정·레벨을 골라 카드가 보이는지, 눌렀을 때 교재가 열리는지 본다.

**주의할 점**
- 링크는 `http://` 또는 `https://`로 시작해야 저장된다. 아니면 "웹 링크는 http:// 또는 https://로 시작해야 합니다."가 뜬다.
- 링크를 비우면 사이트에서 "링크 미등록" 안내가 나온다.
- "회원 공개"는 지금 회원 기능이 숨김이라, 방문자가 누르면 "회원 전용 핸드북은 준비 중입니다." 안내만 뜬다.
- "수강생 전용"은 권한을 주는 기능이 아직 없어 누구에게도 열리지 않는다. 숨김과 미구현 목록은 [프로젝트 이해 4-4절](프로젝트이해.md#4-4-숨김미구현-기능).
- 목록 위 "총 ○권 · 과정 ○개"가 사이트 상단 통계에 그대로 쓰인다.

### 1-6. 🎬 강의 관리(M8)

결론: 유튜브 주소 하나로 강의 카드를 만든다. 방문자가 카드를 누르면 유튜브가 새 창으로 열린다.

**사이트에서 보이는 곳**: 학습 홈(`/learn`)과 교육 아카데미(`/education`)의 대표 강의, `/news` 세 창구 현황의 강의 수.

**따라 하기**
1. "🎬 강의 관리"를 누른다.
2. "분류"를 고른다.
3. "재생 시간"을 넣는다. 예: `18:42`.
4. "강의 제목"을 넣는다.
5. "유튜브 강의 주소 또는 영상 ID"에 유튜브 주소를 붙여 넣는다. 예: `https://youtu.be/` 뒤에 영상 번호가 붙은 주소.
6. "썸네일 색 1", "썸네일 색 2"는 그대로 두거나 색을 고른다.
7. "💾 강의 저장"을 누른다.
8. "강의가 저장되었습니다. 사이트에 즉시 반영됩니다."를 확인한다.
9. `/learn`에서 카드를 눌러 맞는 영상이 열리는지 본다.

**주의할 점**
- 주소가 잘못되면 "올바른 YouTube 주소 또는 11자리 영상 ID를 입력하세요."가 뜬다. 영상 ID는 유튜브 주소 끝의 영문·숫자 11자다.
- 유튜브에서 "비공개"로 둔 영상은 카드가 있어도 방문자가 볼 수 없다. 유튜브 쪽 공개 설정을 함께 확인한다.

### 1-7. 🧩 앱 관리(M9)

결론: 앱을 등록·수정할 수는 있지만, 2026-11-12부터 AI 앱 화면(`/apps`)과 신규앱 안내판이 숨김이라 방문자에게는 보이지 않는다. 다시 열 때를 위해 목록을 최신으로 유지하는 메뉴다.

**따라 하기**
1. "🧩 앱 관리"를 누른다.
2. "앱 이름"을 넣는다.
3. "분류 (카드 배지 & 쇼케이스 필터)"를 고른다.
4. "한 줄 소개"를 넣는다.
5. "작동 원리 (마우스 오버 시 표시)"에 두세 문장을 쓴다.
6. "검색 키워드 (쉼표로 구분)"에 방문자가 쓸 법한 말을 넣는다. 예: `탄소, 배출량, 계산기, carbon, LCA`.
7. "실행(App Launch) URL"과 "GitHub URL"을 넣는다. 비우면 사이트에 "준비 중" 안내가 뜬다.
8. "공개일 (신규앱 안내판 정렬 기준)"을 고른다.
9. 오래 새 앱으로 보이게 하려면 "신규앱 안내판에 NEW 로 고정 노출"에 체크한다.
10. "💾 앱 저장"을 누르고 "앱이 저장되었습니다. 사이트에 즉시 반영됩니다."를 확인한다.

**주의할 점**
- 안내 문구에 "사이트에 즉시 반영"이라고 나오지만, 지금은 숨김이라 방문자 화면에서 확인할 곳이 없다. 다만 `/news` 세 창구 현황의 앱 수(11/13 기준 신규 7개·전체 18개)는 바로 바뀐다.
- 공개일이 30일 이내이거나 NEW 고정이면 "신규"로 센다.
- 숨김을 푸는 일은 코드 변경이다(3부, [프로젝트 이해 부록 B](프로젝트이해.md#부록-b-개발자용)의 B-4).

### 1-8. 🏷️ 분류 관리(M10)

결론: 게시물·Q&A·핸드북·강의·AI 앱 다섯 목록의 분류를 한곳에서 만든다. 이름은 언제 바꿔도 이미 올린 글과의 연결이 끊기지 않는다.

**따라 하기: 분류 추가**
1. "🏷️ 분류 관리"를 누른다.
2. 위쪽 영역 단추 "게시물", "Q&A", "핸드북", "강의", "AI 앱" 중 하나를 누른다.
3. 단추 아래 "여기서 만든 분류는 … 쓰입니다." 안내로 어디에 쓰이는지 확인한다.
4. "새 분류 이름"을 넣는다. 예: "채용 공고". 40자까지 된다.
5. "배지 색"에서 "오렌지", "라임", "샌드" 중 하나를 고른다.
6. "➕ 분류 추가"를 누른다.
7. "분류 「채용 공고」이(가) 추가되었습니다."를 확인한다.

**따라 하기: 이름·색·순서 바꾸기**
1. "분류 목록"에서 바꿀 분류의 "이름" 칸을 고친다.
2. 필요하면 "배지 색"을 바꾼다.
3. 그 줄의 "💾 저장"을 누른다.
4. 순서는 "▲"(위로), "▼"(아래로)로 바꾼다. 이 순서가 사이트 필터 단추 순서다.

**따라 하기: 분류 지우기**
1. 지울 분류 줄의 "삭제"를 누른다.
2. 그 분류를 쓰는 글이 있으면 "이 분류를 쓰는 콘텐츠 ○건을 어디로 옮길까요?"가 나온다.
3. "미분류로 두기" 또는 "○○로 옮기기" 중 하나를 고른다.
4. "삭제 확정"을 누른다. 그만두려면 "취소"를 누른다.

**주의할 점**
- 목록의 "○건 사용 중"은 그 분류를 쓰는 글 수, "사용 없음"은 0건이다.
- "저장 값(slug)"은 글과 분류를 잇는 내부 이름이라 바뀌지 않는다. 이름을 "공지"에서 "공지사항"으로 바꿔도 글은 그대로 붙어 있다.
- 목록 위에 "아직 기본 분류입니다."가 보이면 데이터베이스 준비가 안 된 상태다. 편집 내용이 저장되지 않으니 개발자에게 알린다.

### 1-9. 📣 배너 관리(M11)

결론: 배너는 모든 공개 쪽에 뜨는 홍보 팝업이다. "지금 노출하기"와 노출 기간 두 가지가 맞아야 뜬다.

**사이트에서 보이는 곳**: 첫 화면을 포함한 모든 공개 쪽. 방문자가 처음 들어올 때 한 번 뜨고, 카드마다 "오늘 하루 보지 않기"와 "닫기"가 있다. 켠 배너가 여러 개면 나란히 뜬다.

**따라 하기**
1. "📣 배너 관리"를 누른다.
2. 상자 제목이 "새 배너 만들기"인지 본다.
3. "제목"을 넣는다. 예: "12월 교육 모집".
4. "배지"에 제목 위 작은 라벨을 넣는다. 예: "NEW OPEN". 비워도 된다.
5. "본문 (줄바꿈 반영)"에 안내 문구를 쓴다. 400자까지 된다.
6. "📁 이미지 올리기"를 눌러 그림 파일을 고른다.
7. "이미지를 올렸습니다."가 뜨고 미리보기에 그림이 나오는지 본다.
8. "이미지 설명"에 그림 내용을 한 줄로 쓴다. 화면낭독기와 그림이 안 뜰 때 이 글이 읽힌다.
9. "버튼이 열 주소"에 누르면 갈 주소를 넣는다. 예: `https://tenai.kr/news`.
10. "버튼 문구"를 넣는다. 비우면 "자세히 보기"가 된다.
11. "노출 시작"과 "노출 종료" 날짜를 고른다.
12. "정렬 순서"에 숫자를 넣는다. 작은 수가 왼쪽·위에 선다.
13. "지금 노출하기 (끄면 저장만 되고 뜨지 않습니다)"에 체크한다.
14. "💾 배너 저장"을 누른다.
15. "배너가 저장되었습니다."를 확인한다.
16. 목록 위 "지금 뜨는 배너 ○개: …"에 제목이 있는지 본다.
17. 새 시크릿 창에서 `tenai.kr`을 열어 팝업이 뜨는지 확인한다.

**목록의 상태 표시**: "노출 중"(켜짐·기간 안), "예약됨"(켜짐·시작일 전), "기간 지남"(켜짐·종료일 후), "꺼짐"("지금 노출하기" 꺼짐). "현재 노출"이 붙은 배너가 지금 실제로 뜨는 배너다.

목록의 "내리기"/"올리기"는 "지금 노출하기"를 바로 끄고 켠다. "수정"은 위 상자에 내용을 불러온다.

**주의할 점**
- 그림은 PNG·JPG·WebP·GIF·SVG, 5MB 이하만 된다. 가로로 넓은 그림(예: 1200×630)이 잘 맞는다.
- "노출 시작"을 비우면 바로, "노출 종료"를 비우면 끝없이 뜬다. 행사 배너는 종료일을 꼭 넣는다.
- 종료일은 그날 밤 23:59까지 뜬다. 예: 종료 12월 7일이면 12월 7일 하루 종일 뜬다.
- 종료일이 시작일보다 앞이면 "종료일이 시작일보다 앞섭니다. 기간을 다시 확인해 주세요."가 뜨고 저장되지 않는다.
- 배너를 "삭제"하면 올려 둔 그림도 함께 지워지고 되돌릴 수 없다. 다시 쓸 배너는 삭제 대신 "내리기"를 누른다.
- 확인할 때 시크릿 창을 쓰는 이유: 내 브라우저에서 "오늘 하루 보지 않기"를 눌렀다면 그날은 내게 안 뜬다.

## 2부. 상담 신청·Q&A 확인과 답변

결론: 방문자가 남기는 글은 두 곳으로 들어온다. 상담 신청서는 "✉️ 상담 신청"(관리자만 봄), 공개 질문은 "💬 Q&A 관리"(답하고 공개하면 누구나 봄)다. 하루 한 번 이상 둘 다 본다.

| | 상담 신청 | Q&A |
|---|---|---|
| 방문자가 남기는 곳 | 모든 쪽의 상담 신청서, 퀵메뉴 "상담 문의" | `/news`의 "무엇이든 물어보세요" |
| 받는 정보 | 문의 종류, 이름, 소속, 이메일, 전화, 내용 | 이름, 이메일(선택), 질문 |
| 누가 보나 | 관리자만 | 관리자가 "공개"로 돌린 것만 누구나. 이메일은 늘 관리자만 |
| 답하는 방법 | Gmail로 답장(메일) | 관리자 화면에 답 쓰고 공개 |
| 자동 삭제 | 접수 1년 뒤 | 없음 |

### 2-1. ✉️ 상담 신청 처리하기(M3)

결론: 새 신청은 메뉴 옆 숫자로 알 수 있고, "새 신청 → 진행 중 → 끝남" 순서로 상태를 옮기며 처리한다.

**따라 하기**
1. 로그인 뒤 왼쪽 메뉴 "✉️ 상담 신청" 옆에 숫자가 있는지 본다. 숫자는 처리 전 "새 신청" 수다.
2. "✉️ 상담 신청"을 누른다.
3. 위쪽 "새 신청" 단추를 눌러 처리 전 신청만 본다.
4. 신청 한 건의 첫 줄에서 문의 종류(AI 교육, AX 컨설팅, AIDC 컨설팅, AI 시스템 구축, RUNIQ STUDIO, 기타)와 이름·소속을 읽는다.
5. 둘째 줄에서 접수 시각과 "보낸 곳"(신청서를 쓴 쪽 주소)을 본다.
6. 이메일·전화와 본문을 읽는다.
7. "Gmail로 답장"을 누른다. Gmail 쓰기 창이 받는 사람과 제목 "Re: [TEN AI 상담] 문의 종류"가 채워진 채 열린다.
8. Gmail 창에서 답장을 써서 보낸다.
9. 관리자 화면으로 돌아와 "진행 중으로"를 누른다.
10. "상태를 바꿨습니다."를 확인한다.
11. 상담이 끝나면 같은 신청의 "끝냄"을 누른다. 끝낸 날이 기록된다.

**상태 단추 순서**: "새 신청" 상태에서는 "진행 중으로", "진행 중"에서는 "끝냄", "끝남"에서는 "새 신청으로" 단추가 보인다.

**주의할 점**
- 목록은 메뉴를 누를 때 새로 불러온다. 화면을 오래 열어 두었다면 "새로고침"을 누른다.
- "Gmail로 답장"은 지금 브라우저에 로그인된 Gmail 계정으로 열린다. 회사 계정으로 로그인되어 있는지 보낸 사람을 확인한다.
- 전화번호를 누르면 휴대폰에서는 바로 전화가 걸린다.
- "삭제"는 "이 신청을 지울까요? 되돌릴 수 없습니다." 확인 뒤 바로 지운다. 개인정보 삭제 요청을 받은 경우가 아니면 지우지 말고 "끝냄"으로 둔다. 1년이 지나면 저절로 지워진다.
- 신청서를 연 지 3초 안에 보내거나 사람에게 안 보이는 칸이 채워진 신청은 자동 프로그램으로 보고 저장하지 않는다. 방문자는 "접수됐다"는 화면을 보지만 목록에는 없다. 방문자가 "보냈는데 답이 없다"고 하면 이 경우일 수 있다.
- 신청 내용은 개인정보다. 캡처해서 메신저로 돌리지 않는다. 방침은 [프로젝트 이해 2-6절](프로젝트이해.md#2-6-개인정보처리방침과-이용약관이-왜-필요한가).

### 2-2. 💬 Q&A 답변하고 공개하기(M6)

결론: 순서는 "답 쓰기 → 저장 → 공개로" 세 번이다. 답을 저장하지 않으면 공개할 수 없다.

**따라 하기**
1. "💬 Q&A 관리"를 누른다.
2. 위쪽 "답변 대기"를 누른다.
3. 질문 한 건의 "Q." 뒤 질문을 읽는다. 첫 줄에 "답변 대기"/"비공개" 표시, 이름, 이메일(남긴 경우)이 있다.
4. "분류"에서 맞는 분류를 고른다. 모르면 "미분류"로 둔다.
5. 아래 칸("답변을 입력하세요")에 답을 쓴다.
6. "분류 · 답변 저장"을 누른다.
7. "저장되었습니다."를 확인한다. 표시가 "답변 완료"로 바뀐다.
8. 이 질문과 답을 사이트에 보이게 하려면 "공개로"를 누른다.
9. "사이트에 공개되었습니다."를 확인한다.
10. `tenai.kr/news`의 "자주 나온 질문과 답변"에서 질문과 답이 보이는지 본다.

**주의할 점**
- 답을 저장하기 전에 "공개로"를 누르면 "답변을 먼저 저장한 뒤 공개할 수 있습니다."가 뜬다.
- 답 칸을 비우고 저장하면 "답변이 비워져 대기 상태로 변경되었습니다."가 뜨고 "답변 대기"로 돌아간다.
- 공개된 질문을 내리려면 "비공개로"를 누른다. 지우지 않아도 사이트에서 사라진다.
- 질문자의 이메일은 공개해도 사이트에 나오지 않는다. 답을 메일로도 보내고 싶으면 이메일을 보고 따로 메일을 쓴다.
- 질문에 전화번호·주소 같은 개인정보가 들어 있으면 공개하지 않는다. 답만 메일로 보낸다.
- "삭제"는 "이 질문을 삭제할까요? 되돌릴 수 없습니다." 확인 뒤 지운다. 광고·장난 글만 지운다.
- "분류 · 답변 저장" 뒤 "답변은 저장했지만 분류는 저장하지 못했습니다."가 뜨면 답은 저장된 것이다. 분류 문제는 개발자에게 알린다.

## 3부. 코드 고쳐 배포하기

결론: 디자인·쪽 구조·방침 문구처럼 관리자 화면에 없는 것은 코드를 고친다. 길은 "저장소 → 가지 → PR → 합치기 → Netlify 자동 배포 → 확인"이고, 잘못되면 "이전 배포 다시 올리기"로 몇 분 안에 되돌린다. 개념은 [프로젝트 이해 2-4절](프로젝트이해.md#2-4-저장소와-배포-고친-내용이-사이트에-올라가는-길).

이 부의 독자는 개발자다. 운영 담당자는 "관리자 화면 메뉴에 칸이 없는 것은 전부 3부의 일"이라는 것만 알면 된다.

용어: 저장소(코드와 바뀐 기록 전체, 회사 GitHub 조직 계정에 있다), main(실제 사이트로 나가는 원본 가지), 가지(원본을 건드리지 않는 작업 사본), PR(가지를 main에 합쳐 달라는 요청서, 11/13 기준 #34까지), 빌드(사이트용 파일로 묶기), Netlify(main을 지켜보다 자동으로 빌드·배포하는 호스팅 서비스).

### 3-1. 처음 한 번: 준비

1. 저장소 쓰기 권한이 있는 GitHub 계정을 담당 엔지니어에게 받는다.
2. 컴퓨터에 Git과 Node.js를 설치한다.
3. 저장소를 내려받는다(`git clone`).
4. 저장소 폴더에서 `npm install`을 실행한다.
5. 담당 엔지니어에게 접속 정보 파일(`.env.local`)의 값을 받아 저장소 폴더에 둔다. 이 파일은 저장소에 올리지 않는다.

### 3-2. 따라 하기: 고치고 배포하기

1. 최신 main을 받는다: `git fetch origin` 뒤 `git switch main`, `git pull`.
2. 작업 가지를 만든다: `git switch -c 고칠-내용-이름`. 예: `git switch -c fix-footer-link`.
3. 파일을 고친다.
4. 로컬에서 띄운다: `npm run dev`.
5. 브라우저에서 `http://localhost:8080`을 열어 고친 쪽을 확인한다.
6. 휴대폰 폭에서도 본다(브라우저 개발자 도구의 기기 모드).
7. 배포와 같은 방식으로 묶어 본다: `npm run build`. 오류 없이 끝나는지 본다.
8. 고친 파일만 담는다: `git add 고친파일`.
9. 기록을 남긴다: `git commit -m "무엇을 왜 고쳤는지 한 줄"`.
10. 올린다: `git push -u origin 가지이름`.
11. GitHub 저장소 화면에서 "Compare & pull request"를 눌러 PR을 만든다.
12. PR 본문에 "무엇을, 왜, 어디서 확인하면 되는지"를 쓴다. 비밀 값은 쓰지 않는다.
13. 검토자가 확인하면 "Merge pull request"로 합친다.
14. Netlify 관리 화면의 배포 목록(Deploys)에서 맨 위 배포가 방금 합친 커밋인지 본다.
15. 상태가 "Published"가 될 때까지 기다린다. 보통 몇 분이다.
16. 실제 사이트에서 고친 쪽을 새로고침해 확인한다(3-3).

**주의할 점**
- main에 직접 커밋하지 않는다. 늘 가지 → PR → 합치기다.
- 비밀 값(비밀번호, 키, 데이터베이스 주소)은 파일·커밋·PR 본문 어디에도 적지 않는다.
- 데이터베이스 구조를 바꾸는 일은 저장소의 `supabase-*.sql` 파일로 남기고, 운영 데이터베이스에 실행하기 전에 확인을 받는다. 코드 배포와 따로 움직인다.
- 메뉴·화면 이름을 바꾸면 같은 PR에서 이 매뉴얼과 [프로젝트 이해](프로젝트이해.md)의 해당 부분도 고친다.

### 3-3. 배포 뒤 확인 목록

1. 고친 쪽이 바뀌었는지 본다. 안 바뀌었으면 강력 새로고침(Ctrl+F5)을 한다.
2. 첫 화면 `/`, `/news`, `/education`이 열리는지 본다.
3. 상담 신청서가 열리는지 본다(보내지는 않는다).
4. EN 단추로 영어 화면이 깨지지 않는지 본다.
5. 숨김 주소 `/apps`, `/membership`이 여전히 첫 화면으로 돌아가는지 본다.
6. 휴대폰으로 한 번 연다.

### 3-4. 따라 하기: 되돌리기

결론: 사이트를 급히 되살리는 일(Netlify)과 코드 기록을 되돌리는 일(GitHub)을 둘 다 한다. 앞의 것만 하면 다음 배포 때 잘못된 코드가 다시 올라간다.

**급할 때: 이전 배포 다시 올리기(몇 분)**
1. Netlify 관리 화면에서 홈페이지 사이트의 배포 목록(Deploys)을 연다.
2. 문제가 생기기 직전, 정상이던 배포를 누른다.
3. "Publish deploy"를 누른다.
4. 실제 사이트에서 예전 모습으로 돌아왔는지 본다.

**이어서: 코드 되돌리기**
1. GitHub에서 문제를 일으킨 PR을 연다.
2. "Revert" 단추를 눌러 되돌리기 PR을 만든다.
3. 되돌리기 PR을 합친다.
4. Netlify가 새로 배포한 뒤 사이트를 다시 확인한다.

**주의할 점**
- 되돌리기는 코드만 되돌린다. 관리자 화면에서 바꾼 글·배너·상담 기록은 데이터베이스에 있어서 배포를 되돌려도 그대로다. 글을 잘못 지운 것은 배포로 되살릴 수 없다.

### 3-5. 배포가 안 될 때

1. Netlify 배포 목록에 합친 커밋이 있는지 본다.
2. 없으면 Netlify와 GitHub 저장소 연결이 끊긴 것이다. 10월 저장소 이전 뒤 실제로 끊겼고 11/10에 다시 연결했다. Netlify 사이트 설정의 저장소 연결을 확인한다.
3. 있는데 실패(Failed)면 그 배포의 빌드 기록을 열어 `vite build` 단계의 첫 오류 줄을 찾는다.
4. 빌드 끝의 "글 미리 심기"(검색엔진용 사본 만들기)는 실패해도 빌드를 멈추지 않는다. 사이트는 올라가고 검색용 사본만 예전 것이 남는다.

## 4부. 도메인·방침 관리

결론: 도메인과 개인정보처리방침은 코드보다 사고 비용이 크다. 도메인은 만료일, 방침은 "공지일 + 7일 = 시행일" 규칙 하나만 놓치지 않으면 된다.

### 4-1. 도메인 현황

2026-11-13 확인 값: 주소 tenai.kr, 등록업체 가비아(네임서버도 가비아), 등록일 2025-11-21, **만료일 2027-11-21**. 자동 연장 여부는 확인 안 됨(경영지원이 2026년 12월 중 확인). 네임서버가 방문자를 Netlify로 안내한다.

개념(도메인은 빌리는 것, 명의가 중요한 이유)은 [프로젝트 이해 2-2절](프로젝트이해.md#2-2-도메인-사는-법과-연장하는-법).

### 4-2. 따라 하기: 도메인 연장

1. 만료 60일 전(2027-09-22 무렵)을 회사 일정표에 넣어 둔다.
2. 회사 명의 가비아 계정으로 가비아에 로그인한다.
3. 관리 화면의 도메인 목록에서 tenai.kr을 찾는다.
4. 만료일이 2027-11-21인지 확인한다.
5. 기간 연장을 고르고 기간(1년 이상)을 정한다.
6. 결제는 결제 권한이 있는 담당자가 한다.
7. 결제 뒤 만료일이 늘어났는지 다시 본다.
8. 자동 연장을 켜고, 등록된 결제 카드의 유효기간도 확인한다.

**주의할 점**
- 만료되면 사이트와 회사 메일이 함께 멈춘다. 유예 기간이 지나면 남이 이 주소를 가져갈 수 있다.
- 등록자(소유자)가 회사 명의인지, 연락 메일이 회사 공용 메일인지 연장 때마다 확인한다.
- 네임서버나 DNS 값은 바꾸지 않는다. 바꾸면 사이트가 바로 끊긴다. 바꿀 일이 있으면 개발자와 함께 한다.

### 4-3. 따라 하기: 개인정보처리방침 고치기

결론: 방침은 "내용 정리 → 시행일 계산 → 코드 수정 → 대표 승인 → 합치기(=공지)" 순서다. 합친 날이 공지일이고, 시행일은 공지일보다 7일 이상 뒤여야 한다.

**언제 고치나**: 받는 개인정보가 늘거나(새 신청서, 회원가입), 맡기는 업체(수탁자)가 바뀌거나, 보관 기간·보관 국가가 바뀔 때.

**시행일 계산(방침 9조)**: 일반 변경은 시행 7일 전 공지, 이용자 권리에 중대한 변경은 30일 전 공지. 예: 11월 13일에 합치면 일반 변경의 시행일은 11월 20일 이후다.

1. 바뀌는 내용을 한 장으로 정리한다: 무엇을 새로 받는지, 왜, 얼마나 보관하는지, 누구에게 맡기는지, 어느 나라에 저장하는지.
2. 일반 변경인지 중대한 변경인지 정하고 시행일을 계산한다.
3. 작업 가지를 만든다(3-2의 1~2단계).
4. `privacy.html`을 연다.
5. 맨 위 "시행일 2026년 9월 18일" 줄 아래에 개정 안내 문단을 하나 더한다. 기존 안내 문단(예: "추가 — 2026년 11월 10일부터 …")과 같은 모양으로, "무엇이 언제부터, 함께 바뀌는 곳"을 쓴다.
6. 본문의 해당 조항(1조 수집 항목, 2조 보유 기간, 4조 수탁자 표 등)을 고친다.
7. 영어 번역 사전 `public/i18n/en/privacy.json`에 새 문장의 영어를 넣는다. 약관에도 걸리면 `terms.html`과 `public/i18n/en/terms.json`도 고친다.
8. PR을 만든다. 본문에 공지일·시행일과 바뀌는 조항을 쓴다.
9. 대표(개인정보 보호책임자 승인 포함)의 문구 승인을 받는다.
10. 공지하려는 날 PR을 합친다. 이날이 공지일이다.
11. 배포 뒤 `tenai.kr/privacy` 맨 위에 개정 안내가 보이는지 본다.
12. 시행일에 실제 기능(새 신청서 등)이 열리는지 함께 맞춘다. 기능이 방침보다 먼저 열리면 안 된다.

**지금 열려 있는 방침 일(11/13 기준)**
- PR #33(11/20 개정 예고)은 합쳐지지 않았다. 회원가입과 함께 내려던 안이라, 회원가입 보류 중에 합칠지 닫을지 대표가 다음 화요일 주간 리뷰에서 정한다.
- 방침 4조에 Supabase 보관 국가가 "미국 등"으로 적혀 있고, 대한민국(서울)으로 고치는 안이 PR #33 안에 있다. 따로 떼어 처리할지 같은 리뷰에서 정한다.

### 4-4. 관리자 비밀번호 다시 정하기(개발자)

1. 운영 담당자에게 요청 시각과 사유를 받는다.
2. 담당 엔지니어가 저장소의 `supabase-admin-account.sql` 절차대로 Supabase에서 아이디·비밀번호를 다시 정한다.
3. 새 비밀번호를 운영 담당자에게 직접 전달한다. 메신저 기록에 남기지 않는다.
4. 운영 담당자가 로그인해 메뉴 10개가 보이는지 확인한다.

관리자 권한은 계정에 붙은 표시로 정해지므로 비밀번호를 바꿔도 권한은 그대로다.

| 8 | 방문자가 상담을 보냈다는데 목록에 없다 | 3초 안에 보내 자동 프로그램으로 걸러짐, 같은 이메일로 1시간에 3건 넘게 보냄, 또는 목록이 옛것 | "새로고침" → 없으면 메일로 다시 받는다 |
| 9 | 접속 통계에 "로컬 모드에서는 접속 통계를 볼 수 없습니다."나 "SQL 을 아직 실행하지 않았습니다"가 뜬다 | 데이터베이스 연결·준비 문제 | 개발자에게 알린다 |
| 10 | 분류 목록 위에 "아직 기본 분류입니다."가 뜬다 | 분류 저장용 표가 데이터베이스에 없음 | 개발자에게 알린다. 그 전까지 분류 편집은 저장되지 않는다 |
| 11 | 코드를 합쳤는데 사이트가 그대로다 | 배포 진행 중, 실패, 저장소 연결 끊김 | 3-5 순서대로 |

## 자주 묻는 질문

결론: "관리자 화면에 칸이 있으면 직접, 없으면 개발자"가 거의 모든 질문의 답이다.

**1. 관리자 화면에서 바꾸면 얼마나 걸려 사이트에 나오나요?**
저장 즉시다. 방문자가 쪽을 새로 열면 바로 보인다. 배포를 기다리지 않는다.

**2. 첫 화면의 큰 제목이나 사진은 어디서 바꾸나요?**
관리자 화면에는 칸이 없다. "메인 타이틀 1·2행"은 학습 홈 큰 제목에만 걸리고, 첫 화면(`/`)·회사 홈(`/biz`)의 제목과 사진은 코드 변경(3부)이다.

**3. 실수로 글을 지웠어요. 되살릴 수 있나요?**
관리자 화면의 삭제는 되돌릴 수 없다. 배포 되돌리기로도 안 된다(3-4). 데이터베이스 백업이 있는지는 개발자가 확인해야 하며, 백업 주기는 아직 확인 전이다([프로젝트 이해 9장](프로젝트이해.md#9-한계와-남은-일)). 지우기 전에 내용을 복사해 둔다.

**4. 새 소식이 검색(네이버·구글)에 언제 나오나요?**
사람이 보는 화면은 즉시 바뀌지만, 검색 로봇이 읽는 사본은 다음 배포 때 새로 만든다. 급하면 개발자에게 다시 배포를 부탁한다. 그 뒤에도 검색엔진이 다시 읽어 가는 데 시간이 걸린다.

**5. 관리자를 여러 명 둘 수 있나요?**
관리자 권한 표시가 붙은 계정이면 누구나 들어올 수 있다. 계정을 늘리는 일은 개발자가 데이터베이스에서 한다. 한 계정을 여러 사람이 나눠 쓰지 않는 것이 좋다. 누가 바꿨는지 구분이 안 되기 때문이다.

**6. 상담 신청이 들어오면 메일로 알림이 오나요?**
오지 않는다. 관리자 화면 "✉️ 상담 신청" 옆 숫자로 확인한다. 하루 한 번 이상 들어가 본다.

**7. 회원가입과 AI 앱은 언제 다시 열리나요?**
2026-11-12부터 임시 비공개이고, 다시 열지는 대표가 결정한다. 결정되면 개발자가 한 번의 PR로 되돌린다. 그 사이 "🧩 앱 관리"에 등록한 앱은 그대로 남아 있다가 열릴 때 함께 보인다.

**8. 방문 통계로 특정 회사가 들어왔는지 알 수 있나요?**
알 수 없다. 개인정보처리방침에 "개인을 알아볼 수 없는 형태"로만 센다고 약속했기 때문에 IP 주소·이름·방문자 번호를 남기지 않는다.

## 용어 풀이

| 용어 | 한 줄 풀이 |
|---|---|
| 관리자 콘솔 | `/admin`. 코드 없이 글을 고치는 관리 화면 |
| 데이터베이스(Supabase) | 글·문의·방문 기록을 표로 저장하는 클라우드 창고 |
| 로컬 모드 | 데이터베이스에 연결되지 않아 그 브라우저에만 저장되는 비상 상태 |
| 분류 / slug | 목록을 나누는 이름표 / 그 이름표의 바뀌지 않는 내부 이름 |
| 방문자 / 페이지뷰 / 방문 수 | 하루 들어온 사람 수 / 열린 쪽 수 / 새로 들어온 횟수 |
| 시크릿 창 | 저장된 기록 없이 여는 브라우저 창. 처음 온 방문자처럼 볼 때 쓴다 |
| 되돌리기(Revert) | 합친 변경을 취소하는 새 변경을 만드는 일 |
| 개인정보처리방침 / 시행일 | 개인정보를 어떻게 다루는지 공개하는 안내문 / 새 내용이 효력을 갖는 날 |

더 많은 용어는 [프로젝트 이해 용어 풀이](프로젝트이해.md#용어-풀이)에 있다.

## 부록. 개발자용

- 관리자 콘솔: `admin.html` 안 스크립트 3묶음(일반 메뉴 / 접속 통계 / 상담 신청). 데이터 읽기·쓰기는 `data-store.js`의 `TenStore`, 기본 분류·배지 색은 `categories-default.mjs`.
- 사이트 설정 반영: `site.js`의 `applySettings`. `data-set` 속성이 붙은 자리만 바뀐다. `heroTitle1`·`heroTitle2`가 붙은 공개 쪽은 `learn.html` 하나라, 첫 화면에 걸려면 `index.html`에 같은 자리를 만들어야 한다.
- 검색엔진용 사본: `prerender.mjs`(핸드북·강의·앱·소식만 심고, 사이트 설정은 심지 않는다).
- 데이터베이스 준비: `supabase-inquiries.sql`(상담), `supabase-visits.sql`(통계), `supabase-categories.sql`(분류), `supabase-banners.sql`(배너), `supabase-admin-account.sql`(관리자 계정).
- 배포 규칙: `netlify.toml`(빌드 `npm run build`, 결과 `dist`, 임시 비공개 302). 방침·약관: `privacy.html`, `terms.html`, `public/i18n/en/privacy.json`, `public/i18n/en/terms.json`.
